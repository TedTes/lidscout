Next.js 14 — Frontend

App Router · TypeScript · Tailwind · Vercel

Key Components

  • NicheGapsView — gaps, pipeline progress strip
  • DashboardNav — sidebar, niche switcher
  • AgentStatusPill — running/idle/failed header pill
  • PipelineProgressStrip — 4-step progress with counts
  • RecentDecisionsFeed — live keep/filter mini-feed

Polling Behaviour

  • Every 15 s — /pipeline/status (pending·running·done·failed)
  • Every 2 s while running — /pipeline/live-feed (ticker + decisions)
  • Every 5 s while running — /agent/activity (coarse events)
  • Polls stop on run complete or 404

API Client

  • axios · JWT Bearer interceptor · auto 401 redirect
  • TypeScript types in lib/types/signals.ts
  • Singleton SignalApiService in lib/api.ts
  • NEXT_PUBLIC_API_URL → FastAPI base URL

FastAPI — Backend API

Python · uvicorn · Railway (SERVICE_TYPE=api)

Market Routes

  • GET/POST /markets — list, create
  • POST /markets/{id}/apply-template → enqueues pipeline
  • GET /markets/{id}/pipeline/status
  • GET /markets/{id}/pipeline/live-feed
  • GET /markets/{id}/agent/activity

Signal Routes

  • GET /signals, /clusters, /opportunities
  • POST /opportunities/{id}/feedback
  • GET /markets/{id}/sources, /companies
  • GET /pipeline/schedule
  • POST /auth/login, /auth/google

Dependency Injection

  • SignalApiDependencies — wires all repos
  • Single Postgres connection per request
  • LLM + embedding + email clients injected
  • Source adapters: JSON, Static, Reddit
  • In-memory repos for local dev
Task dispatch: calls celery_app.send_task("workers.tasks.run_pipeline_for_market") via Redis — fire and forget

Redis — Message Broker

Celery broker + result backend · Railway Redis · REDIS_URL

As Celery Broker

  • Receives tasks from FastAPI via send_task()
  • Receives scheduled tasks from Celery Beat
  • Queues run_pipeline_for_market messages
  • Queues run_daily_pipeline_all coordinator
  • JSON task serialisation

As Result Backend

  • Stores task return values (pipeline summaries)
  • Tracks state: PENDING → STARTED → SUCCESS/FAILURE
  • Results TTL: 24 h by default
  • task_always_eager=True in tests bypasses Redis

Celery Beat — Scheduler

Cron-based · combined with worker in single-instance mode

Schedule

  • Default: 08:00 UTC daily (cron: 0 8 * * *)
  • Configured via PIPELINE_SCHEDULE env var
  • Beat state in celerybeat-schedule.db
  • Validates cron string on startup (raises ValueError if bad)

What It Triggers

  • Enqueues run_daily_pipeline_all
  • Coordinator scans all niches with enabled sources
  • Fans out one run_pipeline_for_market per niche
  • For multiple workers: run Beat as SERVICE_TYPE=beat

Celery Worker — Pipeline Executor

Railway (SERVICE_TYPE=worker) · retries on transient errors

Pipeline Stages

  • ① Fetch Posts — SourceResolver + adapters
  • ② Rule Filter — keyword/category rules (cheap)
  • ③ LLM Relevance — gpt-4o-mini per post
  • ④ Extract Signals — pain, urgency, severity, JTBD
  • ⑤ Score + Embed — ScoringService + text-embedding-3-small
  • ⑥ Cluster — cosine similarity grouping
  • ⑦ Synthesize Opportunities — LLM gap synthesis
  • ⑧ Email Report — Resend HTML digest

Telemetry Events

  • run_started / run_completed
  • sources_scanned — with per-source post list
  • post_evaluating — before each LLM call (ticker)
  • post_accepted / post_filtered — with reason
  • signals_extracted, clusters_formed, gaps_synthesized
  • All written to agent_activity table (fire-and-forget)

Reliability

  • Max 3 retries with exponential backoff
  • No retry on ValueError (config errors)
  • Activity writes wrapped in try/except — never crash pipeline
  • Concurrency: WORKER_CONCURRENCY env

PostgreSQL — Primary Database

Supabase managed · psycopg2 · migrations via Supabase CLI

Pipeline Tables

  • raw_posts — deduped by (source, source_id)
  • signals — extracted pain signals
  • signal_clusters — grouped themes
  • opportunities — synthesized gaps
  • pipeline_run_metrics

Niche Tables

  • users, user_niches, niches
  • niche_sources — tier, quality, access metadata
  • niche_companies, source_locators

Agent Tables

  • agent_activity — JSONB metadata, event_type CHECK
  • agent_preferences, agent_feedback
  • agent_alerts, agent_follow_ups
  • ON CONFLICT DO NOTHING — idempotent writes

OpenAI API — LLM Processing

3 model roles · Responses API · LLM_API_KEY env

Relevance Filter

  • Model: OPENAI_RELEVANCE_MODEL (gpt-4o-mini)
  • Structured JSON output: is_relevant, rejection_category, reason
  • Categories: wrong_subject, promotional, news, job_posting, no_pain_signal

Signal Extraction

  • Model: OPENAI_RESPONSE_MODEL
  • Extracts: pain, urgency, severity, willingness_to_pay, JTBD, user_type
  • One call per relevant post

Embeddings

  • Model: OPENAI_EMBEDDING_MODEL (text-embedding-3-small)
  • 1536-dim vectors for clustering
  • Cosine similarity threshold: 0.82

Source Adapters — Data Ingestion

Reddit · Hacker News · GitHub Issues · Stack Overflow · G2 · custom JSON

Adapters

  • Reddit — PRAW OAuth · subreddits
  • JSON URL — HN Algolia, GitHub Issues, SO · configurable items_path
  • Static URL — G2, ProductHunt, review sites

NicheSource Config

  • Stored in niche_sources table
  • Fields: locator, source_type, tier, signal_quality_score, access_mode
  • JSONB options: items_path, limit, agent instructions
  • Health tracking: last_scanned_at, last_error

Resend — Transactional Email

Post-run digest · RESEND_API_KEY · REPORT_RECIPIENT

What Gets Sent

  • HTML digest after each successful pipeline run
  • Top signal clusters, recommended opportunities, emerging pains
  • Generated by ReportingService
  • Recipient: REPORT_RECIPIENT env (required — pipeline raises ValueError if missing)

Auth — Google OAuth + JWT

PKCE OAuth 2.0 · HS256 JWT · ownership checks on every route

Flow

  • Browser → Google consent → auth code → FastAPI callback
  • FastAPI exchanges code → Google ID token → creates/fetches user
  • Returns signed JWT_SECRET HS256 token
  • Frontend stores JWT in localStorage, sends as Bearer
  • axios interceptor auto-redirects to /login on 401

Authorization

  • Every market route calls _get_owned_user_niche()
  • Returns 404 (not 403) to avoid info disclosure
  • Signals/clusters/opportunities also ownership-scoped
  • JWT expiry: JWT_EXPIRY_MINUTES env (default 60)
